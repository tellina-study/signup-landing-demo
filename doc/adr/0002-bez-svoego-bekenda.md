# 2. Своего бэкенда не делаем — заявка уходит на внешний сервис приёма форм

Date: 2026-09-24

## Status

Accepted

## Context

Нужно принимать заявки на демо-урок: имя и email. Объём — единицы заявок в день.
Свой бэкенд для этого означает сервер, базу, деплой, бэкапы, персональные данные на
своей стороне и человека, который за всё это отвечает. Показ заказчику — по фиксированной
дате.

## Decision

Мы будем отправлять заявку прямо со статической страницы на внешний сервис приёма форм.
Своего серверного кода в этом репозитории нет. Конкретный сервис на момент этого решения
не выбран — в `index.html` стоит заглушка `REPLACE_WITH_YOUR_FORM_ID`, endpoint
подставляется перед деплоем и в репозиторий не коммитится.

## Consequences

Стало проще: репозиторий целиком статический, `npm run build` даёт папку, которую можно
положить куда угодно. Персональных данных на нашей стороне не хранится вообще.

Стало сложнее — и это цена, которую надо назвать:

- Доставка заявки зависит от чужой доступности, и мы об этом узнаём только по коду ответа.
  Отсюда повтор при таймауте и ADR-3.
- Форму нельзя проверить end-to-end без сети. В тестах внешний сервис перехватывается
  (`FormPage.stubEndpoint`), то есть «форма отправляет заявку» проверено против стаба, а
  не против живого сервиса. Проверка против живого сервиса остаётся ручной, перед деплоем.
- Смена сервиса — смена контракта запроса; `tests/delivery.spec.ts` придётся править.
