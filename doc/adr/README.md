# doc/adr — решения с долгими последствиями

Формат — Nygard / `adr-tools`: один файл на решение, имя `NNNN-краткое-название.md`,
нумерация сквозная и не переиспользуется. Новый ADR — копия `0000-template.md` со
следующим номером.

Отличие от `DECISIONS.md`: там короткая строка «почему» по любому решению, здесь —
решения, на которые будут ссылаться и которые придётся отменять. Порог: не влезает в три
строки — значит ADR.

**Папка заведена не на дне 0.** Сигнал назван в ADR-1.

## Оглавление

- [1. Записывать архитектурные решения](0001-zapisyvat-arhitekturnye-resheniya.md) — Accepted
- [2. Своего бэкенда не делаем — заявка уходит на внешний сервис приёма форм](0002-bez-svoego-bekenda.md) — Accepted
- [3. Отправка формы — `fetch` с одним повтором по таймауту; обработчик обязан быть идемпотентным](0003-otpravka-formy-s-povtorom.md) — Accepted

Оглавление написано руками: `adr-tools` (который печатает его командой
`adr generate toc`) в этом окружении не установлен — `which adr` пусто. Три записи
руками дешевле установки инструмента; на десятке — уже нет.
