## Цель

Каждое состояние репозитория, которое слайд Семинара 4 показывает как настоящее, должно
существовать в настоящем коммите этого репозитория, с настоящим прогоном за ним. Не
«похоже на слайд» — а «слайд можно проверить командой».

## Как проверю

- `npm run build` завершается кодом 0; `npx playwright test` зелёный.
- `find . -name node_modules -prune -o \( -name CLAUDE.md -o -name AGENTS.md \) -print` находит
  только корневые — ни `tests/CLAUDE.md`, ни `src/CLAUDE.md` (целевой ответ кейса 1.3).
- Каждая ссылка из кода и из ADR на файл репозитория ведёт на существующий файл.
- Обещание комментария к `submitForm()` («ровно один повтор») ломается мутацией, и тест это
  ловит — иначе комментарий ничем не удерживается.
- **Каждый SHA, названный в этом файле, достижим с опубликованной ветки.** Проверка — не
  `git cat-file -t`: в клоне, где делалась работа, он проходит и на объектах, которые
  осиротил собственный `rebase`. Проверка такая:

  ```
  grep -oE '\`[0-9a-f]{7}\`' .tasks/active/*.md | tr -d '\`' | sort -u | while read s; do
    git merge-base --is-ancestor "$s" origin/seminar-4-arc 2>/dev/null \
      && echo "$s достижим" || echo "$s НЕ ДОСТИЖИМ"
  done
  ```

  Заведено сюда после того, как независимый ROAST нашёл в этом файле три SHA, которых для
  читателя не существует: они остались от первой версии дуги, переписанной `rebase`'ом.
