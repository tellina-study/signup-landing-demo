# signup-landing — демо-репозиторий Семинара 4

Лендинг с формой заявки на демо-урок: одна статическая страница, без бэкенда.

Это **учебный репозиторий**. Ценность здесь не в коде — в истории коммитов: каждый шаг
семинара сделан по-настоящему, и на каждом коммите реально прогнаны сборка и тесты.
Ничего не реконструировано задним числом и ничего не подогнано под текст слайда.

## Ветки

| Ветка | Что в ней |
|---|---|
| `seminar-4-arc` | дуга Семинара 4 целиком: продолжает `main` вперёд — откат хука, затем кейсы 1.2, 1.3, 2.1, 2.2, 2.3 |
| `seminar-5-hook` | ответвление от конца дуги: механический слой — хук защиты ветки и его самотест. Материал Семинара 5, не Семинара 4 |
| `main` | вершина до этой работы (`c0b1a47`). Дуга растёт из неё, а не в стороне от неё |

Почему хук вынесен из дуги: действующая версия Семинара 4 в кейсе 1.2 механизм не ставит.
s19 — «Пока такое действие не названо — механизм ставить рано»; s56 — «оба практических
слоя… хук и процесс… Ответ — на следующем занятии, Семинаре 5».

**`main` не переписан.** Прошлый заход — коммит `10104e8` «Кейс 1.2: ставим хук защиты
ветки» — остался на месте, а дуга начинается с честного отката (`1019546`). Четыре коммита
до дуги целы, с прежними SHA и прежними датами; `force-push` по `main` не делался. То, что в
`git log --graph` видно, как курс поправили, — не побочный эффект: на занятии про честность
это то, что стоит показывать, а не прятать.

**А коммиты самой дуги собирались `rebase`'ом до публикации, и это видно.** Первая версия дуги
ветвилась от `25bd3f0` (до хука); переделка на «поверх `main`» перенесла кейсы черри-пиком, а
кейс 1.3 разбила на два коммита. Даты автора при этом настоящие — они разъезжаются на
одиннадцать минут и идут по цепочке вразнобой, — а даты коммиттера у пяти коммитов совпадают
до секунды:

```
$ git log --format='%h  A:%ad  C:%cd' --date=format:'%H:%M:%S' c0b1a47..seminar-4-arc
76106ac  A:05:32:01  C:05:32:01
14fa124  A:05:11:06  C:05:30:57
3b4b289  A:05:09:57  C:05:30:57
94c5378  A:05:08:19  C:05:30:57
ffbb258  A:05:19:37  C:05:30:57
a1bd73f  A:05:18:11  C:05:30:57
1019546  A:05:30:49  C:05:30:49
```

Это подпись `rebase`, и она здесь не спрятана: rebase своей неопубликованной ветки — обычная
практика, а вот утверждать «ни один коммит не переписан», переписав пять, было бы ровно тем,
против чего это занятие. Ни одна дата не подделана: авторские — те, в которые работа правда
делалась, коммиттерские — те, в которые ветка была собрана в нынешний вид.

**Кейс 1.3 разложен на две правки с разным обоснованием, и это не формальность.**
`a1bd73f` — **класс A**: s27 (строка 39 и речь фасилитатора, строка 56) утверждает, что
конвенция «уже воплощена в ТРЁХ существующих тестах», а в репозитории был один файл тестов и
ни одного объекта страницы. Утверждение о существующем репозитории было ложным — такое
чинится обязательно. `ffbb258` — **класс C**: продукту можно быть полнее семинара. Посылка
кейса 1.3 в самом семинаре названа гипотетической, поэтому `submitForm()` сделана настоящей
не «потому что слайд требует», а потому что без неё первый из трёх адресов знания нечем
показать живым кодом.

## Где что смотреть по кейсам

- **Кейс 1.2, итоговый `CLAUDE.md`** — `git show 1019546:CLAUDE.md`. **15 строк**, не 13:
  кроме критерия готовности и границы на деплой в нём есть разовый шаг
  `npx playwright install chromium`, без которого падают сразу все тесты, мгновенно и не
  по делу. Это проверено на чистом клоне, а не предположено.
- **Кейс 1.3, первый адрес знания** — комментарий к `submitForm()` в `src/main.js`. Он не
  украшение: из повтора по таймауту следует требование к чужой системе (обработчик сервиса
  обязан быть идемпотентным), и это требование удерживается `tests/delivery.spec.ts`, а не
  доверием к тому, что комментарий прочитают. Проверено мутацией: `MAX_ATTEMPTS` 2 → 3 роняет
  тест «is not retried a third time».
- **Кейс 1.3, второй адрес** — его здесь намеренно нет. Конвенция папки `tests/`
  («взаимодействие со страницей идёт через объект страницы, а не по селекторам») воплощена
  в самих тестах: агент, открывший любой спек, видит её в коде. Отдельного файла-правила
  не заведено — по порогу самого семинара, пока конвенция помещается в две строки, новый
  механизм дороже двух строк.
- **Кейс 2.1** — `DECISIONS.md`. Одна запись, и она настоящая.
- **Кейс 2.2** — `doc/adr/`. Порог назван в ADR-1, цена решения — в `Consequences` каждой
  записи, включая неприятную: доставка заявки проверена против стаба, а не против живого
  сервиса (ADR-2).
- **Кейс 2.3** — `.tasks/active/`. В файле задачи стоят статусы на каждом шаге и дословный
  вывод команд, а не «всё работает».

## Чем этот репозиторий расходится со слайдами

Названо здесь, а не оставлено читателю в качестве сюрприза. Во всех трёх случаях правым
считается репозиторий: слайд описывает репозиторий, а не наоборот.

1. **s20 говорит «тринадцать строк».** В блоке на самом слайде 12 строк, а настоящий файл
   кейса 1.2 в этом репозитории — 15.
2. **s35 датирует запись в `DECISIONS.md` 2026-09-26**, а его оговорка о провенансе
   называет днём создания репозитория 2026-09-20. Первый коммит здесь сделан 2026-09-23, а
   2026-09-26 на момент записи ещё не наступило. В файле стоит реальная дата записи.
3. **s07 относит практику файла-на-задачу к дню 0**, и здесь семинар прав, а репозиторий
   был неполон: в день-0-коммите `.tasks/` нет. Задним числом это не дописывается — даты в
   git не переставляются, поэтому практика заведена на своём кейсе.

## Запуск

```
npm ci
npx playwright install chromium   # один раз на машину
npm run dev                       # http://localhost:5173
npm run build
npx playwright test               # 8 тестов
```

Без `playwright install` падают сразу все тесты, мгновенно и не по делу:
`browserType.launch: Executable doesn't exist at .../chrome-headless-shell`.
